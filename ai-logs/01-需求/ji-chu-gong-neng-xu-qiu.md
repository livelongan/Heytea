## 3. 详细需求

### REQ-01 登录页

**目标：** 用户可以提交账号密码登录；输入错误时能快速定位并理解错误原因。

**功能要求：**
- 登录表单包含账号和密码字段及登录操作。
- 账号、密码均为必填项；按照项目定义的字段规则校验长度。
- 校验失败时，在对应字段附近展示错误提示，并将焦点或辅助说明关联到出错字段。
- 服务端认证失败时展示明确、可理解的错误文案，不得仅显示“系统异常”等通用提示。
- 登录成功后保存认证 token 和用户信息，并进入登录后的默认页面。
- 提交期间防止重复提交，并提供可感知的加载状态。

**验收标准：**
1. 账号或密码为空时，表单阻止提交，并能分别指出未通过校验的字段。
2. 字段长度不符合规则时，显示对应字段的校验说明。
3. 使用错误凭据登录时，页面展示明确的认证失败提示，表单仍可继续编辑和提交。
4. 使用正确凭据登录时，token 和用户信息写入应用状态，并跳转至主页面。
5. 登录请求处理中，提交按钮体现处理中状态且不能重复触发请求。

### REQ-02 路由守卫

**目标：** 根据登录状态控制受保护页面访问，并在退出时清理认证状态。

**功能要求：**
- 未登录用户访问 `/dashboard`、`/scenarios/:scenarioId`、`/exam` 等受保护路由时，跳转到 `/login`。
- 用户从受保护路由被拦截后，登录成功应返回原目标页面；若没有原目标，则进入默认主页面。
- 已登录用户访问 `/login` 时，跳转至默认主页面。
- 用户退出登录时，清除 token、用户信息、Zustand 持久化状态及相关本地缓存，再跳转到登录页。
- 退出后再次访问受保护路由仍应被拦截；刷新页面也不得恢复已退出的会话。

**验收标准：**
1. 未登录访问 `/dashboard` 时跳转至 `/login`。
2. 未登录访问受保护的场景详情或考试页时同样跳转至 `/login`。
3. 通过受保护地址进入登录流程并登录成功后，返回该地址；没有原目标地址时进入 `/dashboard`。
4. 已登录访问 `/login` 时自动回到 `/dashboard`。
5. 退出后检查应用状态和本地持久化数据，认证信息已清除；重新访问受保护页面会被拦截。

### REQ-03 主框架

**目标：** 为登录后的业务页面提供统一、可定位当前页面的导航框架和内容区域。

**功能要求：**
- 主框架包含侧边菜单、顶部栏和主内容区域。
- 侧边菜单至少提供主页面和考试页面入口；场景详情可从场景列表进入。
- 当前路由对应的菜单项应有明确的激活态；路由变化后激活态同步更新。
- 主内容区域独立滚动，侧边栏在内容滚动时保持固定。
- 页面布局应适配常见桌面及窄屏视口，不得遮挡主要操作和内容。

**验收标准：**
1. 登录后主页面显示统一框架、导航菜单、顶部栏及路由内容。
2. 访问不同菜单对应路由时，仅当前菜单项显示激活态，且状态随路由变化更新。
3. 主内容超出视口时可以滚动；滚动内容不会带动固定侧边栏离开视口。
4. 在窄屏视口下导航和主要内容仍可访问，主要操作不被遮挡。

### REQ-04 404 页面与全局错误边界

**目标：** 对不存在的路由和未捕获的渲染异常提供可恢复的界面，避免白屏。

**功能要求：**
- 访问不存在的路由时显示 404 页面，并提供返回首页的操作。
- 组件渲染发生未捕获异常时，由全局 ErrorBoundary 显示兜底界面，而不是白屏。
- 错误兜底界面应提供重新尝试或返回首页的恢复入口。
- 不在用户界面暴露敏感堆栈、内部路径或未经处理的异常细节。

**验收标准：**
1. 访问不存在的 URL 时显示 404 状态，并能通过“返回首页”进入可用首页。
2. 人为触发受 ErrorBoundary 保护范围内的渲染异常时，显示错误兜底界面且应用不白屏。
3. 错误兜底页的恢复操作可以重新渲染或返回首页。
4. 面向用户的错误页面不显示堆栈和敏感调试信息。

在线考试的完整功能要求及验收标准单独维护于 [在线考试需求](在线考试需求.md)。

## 4. 通用约束

- 所有校验、状态和错误提示需可通过键盘操作和辅助技术识别。
- 页面刷新后，认证状态遵循 REQ-02 的持久化与退出清理规则；考试答案是否在刷新后恢复，应由考试会话策略明确配置。
- 时间、成绩、答题进度和历史记录以服务端确认的交卷结果为准；开发阶段可使用 MSW 模拟服务端响应。
- 本文档中的路由和交互验收结果应由单元测试或端到端测试覆盖；涉及完整登录及考试交卷的主流程优先使用 Playwright 验证。
